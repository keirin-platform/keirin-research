# 競輪の共通認識

競輪の作業（予想、分析、記事の下調べ）で、ドメイン知識と方法論の教訓を共通認識として使うための入口。
事実はすべて知識のファイルにあり、このスキルには書かない。知識を引くときは、ファイルと識別子（例: `RULE-004`）で示す。

このスキルのディレクトリから見て `../../` がリポジトリ（keirin-research）の根。知識は `../../knowledge/`、保留の候補は `../../candidates/` にある。シンボリックリンクで入れているときは、実体の場所で読む。

## 姿勢

- 競輪の基本（ライン、番手、主導権、車番の配置、得点の尺度）は、言われる前に考慮する。選手ごとの成績を独立に並べるだけの分析や予想にしない。
- データは唯一の判断材料だが、絶対ではない。データから見えないものがある（`../../knowledge/blind-spots.md`）。
- オーナーが映像や現地で見たことは、正当な根拠として扱う。データの集計を根拠に退けない。
- 候補（`../../candidates/`）は結論の根拠に使わない。確かめるべき要因の候補としてだけ使う。
- 言葉は競輪の言い方にする。オートレースや競馬の言葉を混ぜない。

## 最初に読むもの

1. `../../knowledge/commitments.md` — 研究の取り決め。予想は確率で出す（`COMMIT-001`）、登録の基準（`COMMIT-002`）、公開してよいもの（`COMMIT-004`）。
2. `../../knowledge/domain/vocabulary.md` — 競輪の言い方と、使わない言い方。答えを書く前に確かめる。

## 知識の地図

|---|---|---|
| `../../knowledge/domain/rules.md` | 規則・事実（級班、競走得点の窓、昇降級の Δ、ミッドナイトの車番、4・6・8番車の慣例、車立て、決まり手と B・H・S、払戻率、ガールズ） | 要因を挙げるとき、数字を確かめるとき |
| `../../knowledge/domain/mechanisms.md` | レースの仕組み（ライン、主導権と決まり方、番組編成と実力の配置） | 何が結果に効きうるかを考えるとき |
| `../../knowledge/domain/laws.md` | 自分たちのデータで確かめた法則（確認済み・否定） | 傾向を使うとき、結論の根拠にするとき |
| `../../knowledge/domain/vocabulary.md` | 用語と避ける言い方 | 答えを書く前 |
| `../../knowledge/methodology.md` | 統計の方法論（検出力、実力と構成のそろえ方、縮小推定、未来の情報、着順の非独立、個人差の検定） | 分析を設計するとき、結論を書くとき |
| `../../knowledge/commitments.md` | 研究の取り決め | 予想を出すとき、登録するとき、公開するとき |
| `../../knowledge/sources/keirin-jp.md` | KEIRIN.JP の性質（遡れる範囲、並びは予想、周回の位置がない、コメント、利用条件） | 取得元をまたぐとき、期間を決めるとき |
| `../../knowledge/sources/oddspark.md` | オッズパークの性質（過去分の並び、取得の停止、引用の禁止） | 並びを使うとき、公開するとき |
| `../../knowledge/data/keirin-data.md` | keirin-data の表・列・空の値・期間、本物の並びと推定の並び | データを読む・クエリを書くとき |
| `../../knowledge/field-dictionary.md` | ファンの言葉とデータの項目の対応表（何を測り、何を区別できないか） | 項目を選ぶとき、指標や特徴を作るとき |
| `../../knowledge/blind-spots.md` | データから見えないものと、結論を歪める向き | 設計するとき、結論を書くとき、食い違ったとき |
| `../../candidates/` | 保留の候補（テーマごと: ライン、脚質、選手、条件、配当）。README から読む | 要因を挙げるとき、同じ通説を調べ直す前 |

## 段階ごとのスキル

| 段階 | スキル |
|---|---|
| 何かを調べる・確かめる・集計する・指標や特徴を作る・予想を組み立てる・レースや選手を評価する前 | `designing-keirin-analysis` |
| 集計の結果から結論やまとめを書くとき、過去の結論を使うとき | `concluding-keirin-analysis` |
| オーナーの観察（映像・現地）がデータの集計や答えと食い違ったとき | `handling-keirin-observation-conflicts` |
| 新しい知識を残すとき、保留にするとき、既存の知識の誤りや訂正が分かったとき | `registering-keirin-knowledge` |

数字を1つ確かめるだけのような小さな問いでは、知識を引いて簡潔に答える。重い手順を踏まない。
