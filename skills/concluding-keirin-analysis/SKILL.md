# 結論を書く前の見直し

集計の数字が出たところが、いちばん間違えやすい。結論を書く前に、方法論で見直し、結論の形をそろえる。
このスキルのディレクトリから見て `../../` がリポジトリの根。事実はこのスキルに書かない。示したファイルを読み、知識を識別子つきで引く。

## 1. 方法論で見直す

`../../knowledge/methodology.md` を読み、この結果に当てはまる項目で確かめる。少なくとも:

- **母集団と除外** — 何を対象にし、何をどれだけ除いたか。欠場・失格・同着の扱い（`DATA-KD-004`）。条件ごとに除外の割合が偏っていないか。
- **実力と構成** — 比べた群の実力（得点）と構成（種目・車立て・時間帯・級班・グレード）がそろっているか（`METH-002`、`METH-003`）。車番を比べたなら、ミッドナイトと4・6・8番車の配置を外したか（`MECH-003`）。
- **ライン** — 同じレースの選手を独立に数えていないか（`METH-006`）。推定の並びを使ったなら、効果は控えめに出ている（`DATA-KD-003`）。
- **検出力** — 有意でなかったなら、件数から検出力を見積もり、「差がない」とは書かない（`METH-001`）。
- **検証** — その時点より前のデータだけを使ったか（`METH-005`）、95% 区間と前半・後半の再現を見たか（`COMMIT-002`、`METH-008`）。まだなら、まだと書く。

過去の結論を使うときは、そのときの期間と件数まで遡る。候補（`../../candidates/`）の「前回の試算」は参考値で、結論の根拠にしない。

## 2. 結論の形

結論は次の形で書く:

- **結論** — 何が言えるか。言える範囲（期間・条件・母集団）の中で書く。
- **確かさ** — 何で確かめ、何がまだか（区間、前半と後半、偽のラベルでの確認、映像での照合など）。
- **データから見えないもの** — `../../knowledge/blind-spots.md` から、この結論に効きうるものを挙げ、「データで見えない〇〇の影響を受けうる」と添える。見えない要因が効く問いでは言い切らない。
- **前提にした知識** — 使った知識の識別子（例: `RULE-004`、`METH-006`）。
- **母集団と期間** — 対象と期間、件数。

否定的な結論も、「試した範囲（方法・条件・期間）では出なかった」までしか言わない。予想の結果は確率の正確さで述べ、車券や回収率の話にしない（`COMMIT-001`）。

## 3. 登録するか、保留にするか

`../../knowledge/commitments.md` の `COMMIT-002` で、この結果が「確認済み」「否定」「保留」のどれに当たるかを判断して示す。
知識として残す価値があれば、`registering-keirin-knowledge` で登録（判断がつかなければ候補への保留）を提案する。公開してよい形（`COMMIT-004`、`COMMIT-005`）にしてから提案する。
