# 観察とデータが食い違ったとき

オーナーが映像（マルチビューなど）や現地で見たことと、データの集計や先の答えが食い違ったとき、データを根拠に反論しない。
データには、周回ごとの位置も実際の並びもレース中の駆け引きも残らない。映像の側が正しいことは十分にある。

このスキルのディレクトリから見て `../../` がリポジトリの根。

## 手順

1. **反論しない。** データの集計を根拠に、オーナーの観察を退けたり疑ったりしない。先の答えが集計から言い過ぎていたなら、そう認める。

2. **データから見えないものを疑う。** `../../knowledge/blind-spots.md` を読み、食い違いの原因になりうる「データに残らないもの」を挙げる（周回ごとの位置、実際の並び、レース中の動き、調子）。

3. **言葉と項目のずれを疑う。** `../../knowledge/field-dictionary.md` を読み、先の答えが使った項目が、オーナーの言葉と同じものを測っていたかを確かめる（たとえば「先行」と脚質の逃、「番手」と予想の並びの位置）。項目が何を区別できないかを示す。

4. **代わりの項目があるか確かめる。** データに、観察と同じものを測れる項目があれば、それでどう確かめられるかを示す。なければ「データでは判定できない」と言い、それ以上集計で争わない。

5. **観察記録を残す提案をする。** オーナーの観察を、観察記録（`OBS`）の下書きにして見せる: 日付・場・レース・内容・関係する知識の識別子・記録日。
   観察記録はレースを特定できるので、Public の keirin-research ではなく、Private の keirin-data の `observations.md` に置く（`COMMIT-004`）。手元では keirin-research の隣に clone した keirin-data（keirin-research の根から見て `../keirin-data/observations.md`）。書式は `../../knowledge/README.md` の「観察記録」。
   オーナーの承認を得てから、keirin-data にブランチを切って書き、`python3 tools/kb.py check --observations ../keirin-data/observations.md`（keirin-research の根で実行）を通して PR を作る。同じ型の食い違いが前にもあれば、それも示す。

6. **一般化できる知見を分ける。** 同じ型の観察が重なり、データから見えないものや言葉と項目のずれとして一般化できるなら、`registering-keirin-knowledge` で keirin-research に登録を提案する。そのときはレースを特定できる記述を入れず、出典に OBS の ID を書く。

言い方は `../../knowledge/domain/vocabulary.md` に従う。
