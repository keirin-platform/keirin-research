# 知識の書き方

このフォルダには、競輪の検証と予想で共通の認識として使う知識を、1件ずつ Markdown で置く。
書式は `python3 tools/kb.py check` が検査する。誤りがあると1行ずつ「`<パス>:<行>: <内容>`」の形で出て、終了コードが 1 になる。

ここに置くのは、公式の資料かデータの構造で確かめた規則・事実と、自分たちのデータで判断がついた法則だけ。
判断がつかず保留にしたものは、リポジトリの根の `candidates.md` に置く（知識ではない）。

## 知識1件の書式

```markdown
## RULE-001 級班と種別

- 内容: S級（SS・S1・S2）、A級（A1・A2・A3）、L級（ガールズ）がある。
- 種別: 規則・事実
- 根拠: 業務方法規程
- 成立期間: 期間の制約なし
- 出典: keirin-platform:docs/score-correction.md@0850049 §1
- 最終確認日: 2026-11-01
- 依存: なし
```

- 見出しは `## <ID> <題>`。値は `- <キー>: <値>`。
- 値の続きは、2つ以上の空白で字下げした行に書ける。字下げした `- ` も値の一部になる。
- ID は `<接頭辞>-<3桁の数字>`（例: `RULE-001`）。同じ ID を2回使わない。次の ID は `python3 tools/kb.py next-id <接頭辞>` で出す。
- 書くのは、いま正しいとされている事実だけ。経緯は git の履歴と、出典の側（keirin-platform の docs など）に任せる。

## 接頭辞と置き場所

接頭辞ごとに置くファイルが決まっている。違うファイルに置くと誤りになる。

| 接頭辞 | 何を書くか | 置き場所 |
|---|---|---|
| `RULE` | 規則・事実（公式の資料かデータの構造で確かめたもの） | `knowledge/domain/rules.md` |
| `MECH` | レースの仕組み | `knowledge/domain/mechanisms.md` |
| `LAW` | 法則（自分たちのデータで確かめた傾向） | `knowledge/domain/laws.md` |
| `TERM` | 用語・避ける言い方 | `knowledge/domain/vocabulary.md` |
| `METH` | 統計の方法論 | `knowledge/methodology.md` |
| `COMMIT` | 研究の取り決め | `knowledge/commitments.md` |
| `SRC-KJ` | KEIRIN.JP の性質 | `knowledge/sources/keirin-jp.md` |
| `SRC-OP` | オッズパークの性質 | `knowledge/sources/oddspark.md` |
| `DATA-KD` | keirin-data の表の性質と期間 | `knowledge/data/keirin-data.md` |
| `FIELD` | ファンの言葉とデータの項目の対応表 | `knowledge/field-dictionary.md` |
| `BLIND` | データから見えないもの | `knowledge/blind-spots.md` |

## キーの一覧

必須キー（すべての接頭辞）:

| キー | 値 |
|---|---|
| `内容` | 知識の本文 |
| `種別` | 下の表のとおり |
| `根拠` | なぜそう言えるか |
| `成立期間` | いつからいつまで成り立つか。制約がなければ `期間の制約なし` |
| `出典` | 下の「出典の書き方」のとおり |
| `最終確認日` | `YYYY-MM-DD` |
| `依存` | `なし`、または依存する ID を「、」か「,」で区切った並び。どの ID も実在すること |

接頭辞ごとに足す必須キー:

| 接頭辞 | 追加の必須キー |
|---|---|
| `LAW` | `状態`・`検証の記録`・`判断が変わりうる条件` |
| `FIELD` | `ファンの言葉`・`項目`・`測っているもの`・`区別できないこと`・`照合` |
| `BLIND` | `歪みの向き` |
| `COMMIT` | `適用範囲` |
| `TERM` | `避ける言い方` |

`LAW` で `種別` が `個人差の有無` のものは、さらに `選手あたりの件数`・`検出力` が必須。

- `検証の記録` には、使ったスクリプト（`keirin-platform:<パス>@<コミット>`）、コマンド、期間、件数、そろえた条件、結果（効果の大きさと 95% 区間、前半と後半）、測る前に決めた実質的な大きさを書く。
- `判断が変わりうる条件` には、どのデータが増えたら確かめ直すか、どの向きに結論が動きうるかを書く。

## 種別と選択肢

| 接頭辞 | `種別` に書けるもの |
|---|---|
| `MECH` | `仕組み` |
| `LAW` | `全体の傾向`・`個人差の有無` |
| `TERM` | `用語` |
| `METH` | `方法論` |
| `COMMIT` | `取り決め` |
| 上以外 | `規則・事実` か `データで確かめた事実` |

- `状態`（LAW）は `確認済み`・`否定` のどちらか。基準は `COMMIT-002`。
- `照合` は `照合済み`・`未照合` のどちらか。
- `最終確認日` は `YYYY-MM-DD`（実在する日付）。

## 出典の書き方

次の形を「、」で区切って並べる。

- `keirin-platform:<リポジトリ内のパス>@<コミット> <節>`。コミットは必須（短い形でよい）。節は書き換わるので、書いたときの版を指す。例: `keirin-platform:docs/score-correction.md@0850049 §3`
- 公式の資料などの URL: `https://…`。後ろに空白と題を付けてよい。
- オーナーから聞いた知識: `オーナー（YYYY-MM-DD の会話）`
- 観察記録から一般化した知識: `keirin-data:observations.md OBS-<3桁>`（keirin-data は Private。検査は形だけを見る）

## 候補（candidates.md）

判断がつかず保留にした通説や問いは、リポジトリの根の `candidates.md` に `CAND-<3桁>` で置く。**結論の根拠には使わない**。設計の段階で、確かめるべき要因の候補として読む。
知識の `依存` に候補の ID を書くことはできない。データが増えて判断がついたら、知識（LAW など）に移して候補を消す。

| キー | 値 |
|---|---|
| `内容` | 通説や問い |
| `文献の根拠` | 外部の集計や記事（URL）。なければ `なし` |
| `保留の理由` | なぜ判断がつかないか |
| `前回の試算` | 自分たちのデータでの前回の集計（期間・件数つき）。なければ `なし` |
| `判断に要るデータ` | 何がどれだけそろえば判断できるか |
| `見直しの時期` | いつ確かめ直すか |
| `最終確認日` | `YYYY-MM-DD` |
| `関係する知識` | `なし`、または知識の ID の並び（実在すること） |

## 観察記録（keirin-data の observations.md）

オーナーが映像や現地で見たことは、レースを特定できるので Private の keirin-data の `observations.md` に `OBS-<3桁>` で置く。
このリポジトリには、観察から一般化した知識だけを、出典に OBS の ID を書いて置く。

| キー | 値 |
|---|---|
| `日付` | レースの日（`YYYY-MM-DD`） |
| `場` | 場名 |
| `レース` | レース番号（例: `7R`） |
| `内容` | 見たこと |
| `関係する知識` | `なし`、または知識か候補の ID の並び |
| `記録日` | 記録した日（`YYYY-MM-DD`） |

検査は `python3 tools/kb.py check --observations ../keirin-data/observations.md`（keirin-research の根から、隣に keirin-data があるとき）。

## 避ける言い方（`TERM` のキー）

「、」区切りで並べる。`/…/` で囲んだものは正規表現、それ以外は文字どおりの語。
正規表現は Python と JavaScript の両方で同じ意味になる書き方（文字クラス・選択・グループ・量指定子・行頭の `^` だけ。後読みなどは使わない）に限る。避ける言い方がなければ `なし`。
知識（vocabulary.md と README を除く）とスキルの各行に、避ける言い方が出てきたら誤りになる。

## 大きさの上限

`knowledge/` の Markdown は1ファイル 30,000 バイトまで（日本語は1文字 3 バイト）。`skills/*/SKILL.md` は 12,000 バイトまで。

## 公開してよいもの

このリポジトリは Public。置いてよいのは、自分たちで集計した統計（件数、割合、検定の結果）と、データのスキーマ（表、列の意味、空の値の意味、期間）だけ。詳しくは `COMMIT-004`。

- 収集データそのもの（出走表、成績、並び、払戻の一覧）とその抜き出しは置かない。
- 選手名、選手登録番号、レースと位置から選手を特定できる記述は置かない。個人差は「あるかどうか」だけを書く（`COMMIT-005`）。
- ビューアの URL、keirin.jp の内部 API の場所と種類の番号は書かない。呼び出し方は keirin-platform の docs に任せる。
- オッズパークの並び予想や短評の文言は書かない（引用も禁止されている）。
